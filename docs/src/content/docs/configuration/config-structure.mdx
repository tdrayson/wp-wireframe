Configs use a flat structure with **promoted common keys** at the field level. Type-specific settings go in `args`.

## Full shape

```php
return [
    'title'    => 'Page Title',              // Optional. Shown in the header.
    'subtitle' => 'A short description',     // Optional. Shown below the title.
    'tabs'     => [
        [
            'id'       => 'tab_id',
            'title'    => 'Tab Label',
            'sections' => [
                [
                    'id'          => 'section_id',
                    'title'       => 'Section Title',
                    'description' => 'Helpful description text.',
                    'fields'      => [
                        [
                            'id'          => 'field_id',
                            'type'        => 'text',
                            'label'       => 'Field Label',
                            'description' => 'Help text below the field.',
                            'default'     => '',
                            'required'    => false,
                            'validation'  => 'min:3|max:100',
                            'columns'     => 6,
                            'conditions'  => [
                                'all' => [
                                    ['field' => 'other_field', 'operator' => 'truthy'],
                                ],
                            ],
                            'args' => [
                                'placeholder' => 'Enter text',
                            ],
                        ],
                    ],
                ],
            ],
        ],
    ],
];
```

## Promoted keys (field level)

These are common to every field type:

| Key           | Type           | Default  | Description                                                                                                |
| ------------- | -------------- | -------- | ---------------------------------------------------------------------------------------------------------- |
| `id`          | `string`       | Required | Unique field identifier within the page.                                                                   |
| `type`        | `string`       | `'text'` | One of the [registered field types](/field-types/text-family/).                                            |
| `label`       | `string`       | `''`     | Display label. Pass `''` explicitly to render no label (the field will still align with labelled siblings).|
| `description` | `string`       | `''`     | Help text below the field. Supports `{field_id}` token interpolation against live form values.             |
| `default`     | `mixed`        | `null`   | Default value, used when no saved value exists.                                                            |
| `required`    | `bool`         | `false`  | Whether the field must have a value at save time.                                                          |
| `validation`  | `string`       | `''`     | Pipe-separated [Rakit validation rules](/features/validation/) — e.g. `'min:3\|max:100'`.                  |
| `columns`     | `int (1..12)`  | `12`     | Grid width. 12 = full row; 6 = half; 4 = third; etc.                                                       |
| `conditions`  | `array`        | `null`   | [Conditional visibility](/features/conditional-visibility/) rules evaluated against current values.        |
| `access`      | `string\|array`| `null`   | [Role / capability gating](/features/role-based-access/). Strictly opt-in.                                 |
| `args`        | `array`        | `[]`     | Type-specific settings — `placeholder`, `rows`, `options`, `multiple`, `mode`, etc.                        |

## Type-specific settings (`args`)

Everything that varies between field types lives under `args`. Some examples:

```php
// Text field
['type' => 'text', 'args' => ['placeholder' => 'Optional placeholder', 'copyable' => true]]

// Textarea
['type' => 'textarea', 'args' => ['rows' => 5, 'placeholder' => '…']]

// Select
['type' => 'select', 'args' => ['options' => ['draft' => 'Draft', 'published' => 'Published']]]

// Repeater
['type' => 'repeater', 'args' => ['subfields' => [ /* … */ ], 'add_button_label' => 'Add row']]
```

See each field type's page in [Field Types](/field-types/text-family/) for the full set.

## Flexible structure — tabs and sections are optional

The full nested shape (`tabs → sections → fields`) is the maximum. You can collapse it when you don't need every level.

### No tabs, no sections — just fields

```php
return [
    'fields' => [
        ['id' => 'name', 'type' => 'text', 'label' => 'Name'],
        ['id' => 'email', 'type' => 'email', 'label' => 'Email'],
    ],
];
```

No tabs are rendered. Fields render in a single card.

### Sections, no tabs

```php
return [
    'sections' => [
        [
            'id'     => 'main',
            'title'  => 'Main Settings',
            'fields' => [
                ['id' => 'name', 'type' => 'text', 'label' => 'Name'],
            ],
        ],
    ],
];
```

The tab bar is suppressed; section cards stack vertically.

<Aside type="tip">
A single tab with one section is the **same as just fields**. The framework strips empty wrappers when it builds the React tree.
</Aside>
