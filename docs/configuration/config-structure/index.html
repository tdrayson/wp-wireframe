Config Structure

Configs use a flat structure with promoted common keys at the field level. Type-specific settings go in args.

Full shape

Section titled “Full shape”

Promoted keys (field level)

Section titled “Promoted keys (field level)”

These are common to every field type:

KeyTypeDefaultDescription
idstringRequiredUnique field identifier within the page.
typestring'text'One of the registered field types.
labelstring''Display label. Pass '' explicitly to render no label (the field will still align with labelled siblings).
descriptionstring''Help text below the field. Supports {field_id} tokens that interpolate live form values, e.g. 'URL: https://example.com/{slug}'.
defaultmixednullDefault value, used when no saved value exists.
requiredboolfalseWhether the field must have a value at save time.
validationstring''Pipe-separated validation rules — e.g. 'min:3|max:100'.
columnsint (1..12)12Grid width. 12 = full row; 6 = half; 4 = third; etc.
conditionsarraynullConditional visibility rules evaluated against current values.
accessstring|arraynullRole / capability gating. Strictly opt-in.
argsarray[]Type-specific settings — placeholder, rows, options, multiple, mode, etc.

Flexible structure — tabs and sections are optional

Section titled “Flexible structure — tabs and sections are optional”

The full nested shape (tabs → sections → fields) is the maximum. You can collapse it when you don’t need every level.

No tabs, no sections — just fields

Section titled “No tabs, no sections — just fields”

No tabs are rendered. Fields render in a single card.

Sections, no tabs

Section titled “Sections, no tabs”

The tab bar is suppressed; section cards stack vertically.

Tip

A single tab with one section is the same as just fields. The framework strips empty wrappers when it builds the React tree.

Schema & validation

Section titled “Schema & validation”

A JSON Schema for the config structure ships at schema/config.schema.json. It covers all three input formats, the common field keys, the conditions DSL, the access shapes, and per-type args constraints (e.g. choice fields require args.options, repeaters require args.subfields). Point your editor at it to get autocomplete and inline validation while authoring JSON configs.

In VS Code, map it in .vscode/settings.json:

Or reference it inline from a JSON config with "$schema": "./vendor/wp-wireframe/schema/config.schema.json".

Runtime check

Section titled “Runtime check”

When WP_DEBUG is enabled, every booted config is linted and structural problems — unknown field types, choice fields missing options, duplicate IDs, out-of-range columns, and so on — are written to the PHP error log. Users with manage_options also see them in a warning notice on other admin screens; Wireframe pages themselves suppress admin notices, so check the log there.

It’s a focused sanity check against the live field registry; the JSON Schema remains the full contract. Nothing runs when WP_DEBUG is off, so production is unaffected.
